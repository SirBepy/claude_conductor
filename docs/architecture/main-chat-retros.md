# Main-chat retros

Read before editing `daemon/subchats/retro.rs`, `mcp/tool_schemas_retro.rs`, the `/hooks/main-chat-retro` route or rule 12 of `SUBCHATS_MAIN_PROMPT`.

- **Main-chat retros (pc-1677).** A subchats-mode main chat writes one retro when Joe tells it to close (rule 12 of `SUBCHATS_MAIN_PROMPT`), through the `main_chat_retro` MCP tool (schema `mcp/tool_schemas_retro.rs`, route `/hooks/main-chat-retro`, logic `daemon/subchats/retro.rs`). Files are `<data_dir>/main-chat-retros<instance suffix>/<YYYY-MM-DD>-<session id first 8>.md`, so a dev or test daemon writes to its own `-dev`/`-<label>` folder. A later session reads them with `Read`/`Grep`; there is no UI. The frontmatter is flat `key: value` lines the daemon stamps itself, never the chat: `version` (`DAEMON_VERSION`, the real release number on an installed app), `session_id`, `chat_title`, `project`, `model`, `effort`, `started`, `closed`, `subs`, `subs_finished`, `subs_blocked`, `subs_by_tier`, `decisions`. Five prose sections follow: What the main chat did, What felt efficient, What felt slow or wasteful, What went wrong, Ideas for main chats. A retro written by hand uses the same frontmatter (`retro::parse_frontmatter`, test-only, reads both). The global `/close` skill is deliberately untouched.
