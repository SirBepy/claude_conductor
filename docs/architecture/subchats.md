# Subchats (main chat, subs, cards, decisions log)

Read before editing anything under `src-tauri/src/daemon/subchats/`, the sub rules in `lifecycle` or the hooks server, `src/views/sessions/main-chat.ts`, `sub-list.ts`, `subchat-view.ts`, `src/shared/chat/subchat-cards.ts` or `permission-modal/askers.ts`.

- **Subchats module map.** A chat with "Use subchats" on (`ChatConfig.subchats_on`) hands jobs Joe names to hidden child chats (subs), whose questions and results show in the main chat's window. Everything daemon-side lives in `src-tauri/src/daemon/subchats/`; add to it rather than spreading logic through lifecycle and hook files. `brief.rs`/`spawn.rs` decide a mode-on `spawn_chat` (required brief, the three tiers, depth 1, cap of 10 started subs (`spawn/cap.rs::started_subs`: a queued sub and a never-started row with no hold hold no slot, since the cap bounds claude processes; the cap is soft: a queued sub that starts later does not re-check it, so a main chat can pass 10 while queued subs start), a duplicate name refused); `held.rs` keeps subs the daemon holds without a child (`after`, the writer queue); `worktree.rs` gives every writing sub (not a gate, not read-only) its own tree and branch at `.claude/worktrees/sub-<id>/tree` (Joe 2026-11-12: no project toggle; `ProjectConfig.subchat_writers` is still parsed and ignored), merged back with a rebase and `merge --ff-only --no-overwrite-ignore`, removed with its branch and its `sub-<id>/` holder (a `.cargo/config.toml` pointing cargo at `sub-<id>/target`, because the shared `D:/cargo-target` kept a ~3GB copy of our crates per tree path that nothing freed) only when merged, clean and with no unpublished submodule commit; removal runs git with `core.longpaths=true` and finishes a delete git gave up on (git stopped at node_modules paths over 260 chars after unregistering the tree, which stranded every tree of 2026-11-10/11), finishes a tree git left half removed, and `restore` retries at boot the trees `on_ended` marked closed (a `closed` file in the holder; a row that ended by an app shutdown or a dead process is never swept). `writers.rs` is the one-writer slot left for subs on the main checkout: a gate (a project-wide gate slot, after merges in flight) and a writer in a folder that cannot have a worktree. `finish.rs`/`turn_end.rs`/`stall.rs`/`stuck.rs`/`ceiling.rs` run a sub's end (`finish_subchat`, the Stop hook's block-nudge-card sequence, the 30-minute card, and `ceiling.rs`'s two cards: past 300 model calls, and context nearly full (90% of the window used, from the transcript's last usage line; once per round, and a long run alone never draws a card, Joe 2026-11-12); a sub queued for the writer slot, `writers::waiting_behind`, is never blocked, nudged or carded as stalled, a turn opened by a new message starts a new block-nudge round, and Joe's failed "Nudge again" draws one "did not help" card, never the same card again); `queue_watch.rs` wakes a main chat once when a sub has waited 5 minutes with nothing in its way (its `after` finished cleanly, the slot is free, or its hold is gone), and `card_watch.rs` wakes it once when a sub's stall card (stuck, stopped, died) has gone 10 minutes without Joe's answer, so a main chat never schedules prompts to poll its subs; `plumbing.rs` is the rule that a sub's plumbing never reaches Joe as a card (Joe 2026-11-12: a sub that could not start, a worktree or bootstrap failure, a refused merge, a conflict the sub did not fix after `merge_followup` told it once, a continued branch that could not be updated): it wakes the main chat once per problem with fixed words, `subchat status` returns what failed as tool data, and the main chat fixes it with `subchat retry` (`held::retry`, start a sub whose start failed), `merge` (`merge_followup::merge_now`, land a finished sub's refused merge) or `drop` (a never-started sub, or giving up a refused merge so its commits stay on the branch), asking Joe only when it needs his decision; a merge refused because another chat has uncommitted changes in the same files raises nothing and wakes nobody: `pending_merges.rs` keeps it on disk and the busy_watchdog tick lands it (`merge_followup::retry_pending`) once those files are clean; every other refused merge is kept in the same file until it lands or is dropped, so `merge_followup::unresolved` keeps an `after` sub waiting across a restart too; a removed-worktree card on an ended sub (`worktree::on_ended`, tree kept or build folder left) is the one plumbing card left, as the record of where unmerged commits sit; `routing.rs` stamps `display_session_id` on question, permission and secret payloads so a sub's card shows in its main chat while `session_id` stays the answer target. `card_log.rs` stores the cards a sub draws in its main chat (`facts.rs` computes their chips from git and the transcript), `back.rs` queues the one line served on Joe's next message, `finish_subchat` requires `decided`, `ruled_out` and `learned` (each a list of at most 8 rows of 200 chars, `["nothing"]` is valid, a refusal names every field left out): `learned` lists what the job taught that stays true, each row naming the memory file or todo id the sub saved it to first with the save step (`~/.claude/refs/save-step.md`), is stored on `FinishRecord` and is deliberately not copied to the decisions log or the digest, `decisions.rs` keeps the decisions log (there is no "checkup" of it: that card read as noise and was removed 2026-11-12, so a finish never runs a model or raises a card), `closing.rs` holds a close that would strand running subs or unmerged worktree commits and moves a family on `respawn` or promotion, `reply.rs` is typing to a sub and "Move to sidebar", `adopt.rs` is the reverse ("Move into main chat" in the chat menu: placeholder brief, an idle child is stopped so the next send relaunches it as a sub, the main chat is woken to hand it a job), `tool.rs` is the `subchat` MCP tool, and `jsonfile.rs` keeps an unreadable state file aside as `.bad` instead of reading it as empty. **The seams:** `subchats::is_sub(&Instance)` is how any list or rule asks "is this a sub" (`subchat_of`, never `worker_of`: a sub must not wake its parent the way a Jarvis worker does); `subchats::on_finished(state, sub_id)` is the one hook a finish fires (card, one line back, decisions, `after` queue, wake); `cards::raise_card` is the only way the daemon puts its own question card in a window; `subchats::role_launch` decides on every launch whether a row is a sub, a main chat or neither. **Data files** are under `<data_dir>/subchats/`: `<main>.cards.jsonl`, `<main>.pending.jsonl`, `<main>.decisions.md`, `<sub>.finish.json`, `<sub>.digest.md`, `<sub>.ceiling.json`, `held[suffix].json` and `pending-merges[suffix].json` (per daemon instance: a test or dev daemon on the same data folder has its own registry, and a shared file let every `cargo test` wipe the live queue, 2026-11-10). A leftover `checkups.json` from an older build is never read. A sub that never started and lost its hold is rebuilt from its brief by `held::recover_lost` only within `RECOVER_WITHIN` (2h) of its spawn; an older one is left to the watchdog and the `subchat drop` action. **Hard rules:** a sub's text never travels inside an `is_meta` message (only as hook context framed as data, `back.rs` and the decisions rider); a sub is never `worker_of`; only the daemon writes the decisions log, so no chat carries it; every field of `held.json`'s and `pending-merges.json`'s entries except the sub id has `#[serde(default)]` and an unreadable file or entry is kept as `.bad`, never read as empty. **A project knows its main chat** (2026-11-12, D1): `ProjectConfig.main_chat_id` (`#[serde(default)]`) names the one live main chat per project. `main_pointer.rs` keeps it true to the registry: `reconcile` keeps a live pointer, replaces a dead one with the project's newest live mode-on chat and clears it when none is left, and runs from `publish_mode_changed` (every mode flip, so a menu flip and the `start_session` rollback), after `start_session` registers a new main chat (its mode is written before the row exists), from `settle_family` (every close path settles after it marks the row ended), and from `heal_orphans` at boot and on the 60 second tick; a `respawn` successor takes the pointer through `hand_over`. The daemon never writes settings.json: it sets its cache and publishes `project_main_chat_set`, which `daemon_link/handlers.rs` merges and persists. The pointer is read by the draft and the sidebar from `list_projects` (`project-main-chats.ts`, re-read on `settings-changed`, the `subchats-on-changed` nudge and at mount), and a reader always checks the chat it names is still open, since the heal can lag a crash by a minute. Closing the pointed chat always asks first (`closing::needs_approval`, `main_chat_line`): closing deletes its Answers and Ask stores (`ask/store.rs::drop_for_chat`) and ends its finished subs, and the pointer clears with it; `APPROVED` keeps the pump's EOF backstop from raising a second card for a close Joe already approved. A new chat in a project with a main chat (`draft-subchats.ts`) shows "Goes to <title>, <project>'s main chat" and a Plain chat instead switch where Use subchats sits, and sends its first message to that chat (`pending-pane-composer.ts::sendToMainChat`, a scheduled message goes there too); with Plain chat instead on the draft is an ordinary chat with the mode off. The sidebar's Main chats group lists only the pointed chat of a project (`listedAsProjectMain`); a second mode-on chat in the project draws in the group its state puts it in. With no pointer loaded (a phone whose project list failed) every mode-on chat lists as before. Frontend: `src/views/sessions/main-chat.ts` (`mainChatInfo`, `showsSubs`: the sidebar row's dots, count, hover and ring), `sub-list.ts` and `subchat-view.ts` (header count, list, reading a sub in place), `src/shared/chat/subchat-cards.ts` and `chat-subchat-card.ts` (cards and chips), `permission-modal/askers.ts` (chips for several askers in one window). What a paired machine sees: `docs/multi-machine.md`.

- **Main chat digest.** A main chat never closes, so no model turn writes its recall digest: `decisions.rs` rewrites `<data dir>/subchats/<main chat session id>.digest.md` from the chat's decisions log every time the log changes (`append_in`, the one write path every card answer and sub finish goes through, plus `move_log` on a respawn), in the same folder and four-section format as a sub's digest. Live `card` and `decided` entries become `## Decided`, `ruled_out` entries `## Rejected`, replaced entries are left out, `## Done` names the subs that reported rows, and `## Open` is `none`; a log with nothing decided or ruled out writes no file. The global `recall` tool ingests it with the sub digests, and only the daemon writes it.
- **Moving a main chat and its subs to another account** (Joe 2026-11-13, D67-D69). The Change account picker (`change-account-modal.ts::openChangeAccountForChat`, opened from the chat menu, the statusbar account chip and the rate-limit banner's Switch account) shows "Also move its N subchats", on by default, on a chat with subs that have not ended. `account-move.ts` then calls `move_session_to_account` once per chat, main first, skipping any already on the target, so a working sub restarts on the new account at once and gets "continue", the same as a single move. Subs started later copy the main chat's account, so they follow with no extra state. API credit is left out of that picker for a sub, a mode-on chat or a chat with subs, and `subchats::refusal_for_move` refuses it in the daemon too, the third door after the mode toggle and the sub spawn. The rate-limit banner never picks a target itself: an account it guessed could be the one that is not working.
