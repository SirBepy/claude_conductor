# Dev daemons, verification rigs and harness scripts

Read before running a dev daemon beside the live app, `scripts/live-verify.ps1`, `phone-verify.ps1`, `wdio-sweep.ps1`, the view harness or a when-done check.

- **Dev daemon serving a phone without bouncing the live app:** build dist, `cargo build --manifest-path src-tauri/Cargo.toml`, then run the daemon binary with `CC_DAEMON_INSTANCE` set (any label) so it binds an ephemeral remote port instead of fighting the production daemon for 27183 - read the actual port from the `remote-access server listening on 127.0.0.1:<port>` log line, or set `CC_REMOTE_PORT` to pin a known one. Point the emulator at `10.0.2.2:<port>`.

- Live-verify against the real app without touching the dev's installed instance: `scripts/live-verify.ps1 up` / `eval <index> <expr>` / `shot <index> <path>` / `down` - isolated debug build, private WebView2 profile, loopback-only CDP on a random ephemeral port, teardown by PID only. Headless by default: the rig runs under server_supervisor docked headless, so neither its windows nor the ones it opens (the Code pop-out) reach Joe's screen or take his focus. `up -Visible` puts it on the desktop instead, and then his typing can land in the rig.

- Phone-path (`isRemote()` true) checks without a device: `scripts/phone-verify.ps1 up` / `status` / `down` runs an isolated daemon from a private copy of `D:\cargo-target\debug\cc-conductor-daemon.exe` (build it first; the script never runs cargo) with a dummy account and a git-initialised scratch project; `e2e/phone/open.mjs`'s `openPhonePage()` returns a logged-in Playwright Pixel 5 page on it. Opening a draft chat and typing in its composer spawns no `claude` process.
- Broker Gate 0 (every kind of chat reads through the broker with zero permission cards): `node scripts/broker-gate0.mjs --daemon <path to cc-conductor-daemon.exe>` (build the daemon first; the script never runs cargo and builds only the fake `claude`). Private instance, scratch data dir under the temp dir, the fake `claude` as the CLI, no broker secret of any kind (random throwaway login values only), no billed run; calls are denials only because a live daemon's secret source includes the real `~/.claude/.env`. It kills only the daemon PID it started and deletes its scratch folder (`--keep` leaves it). Details and gaps in docs/architecture/api-broker.md "Gate 0 and the friction counter".

- Run plan live run (BILLED, real `claude`): `node scripts/run-plan-live.mjs --daemon <cc-conductor-daemon.exe> [--keep] [--config-dir <dir>]` (build the daemon first, `cargo build --bin cc-conductor-daemon`; the script never runs cargo). A private daemon (scratch data dir under `C:\tmp`, own instance label and ports, `CC_DAEMON_NO_AUTOSTART`) with the real CLI; its account entry only REFERENCES the config dir (default `~/.claude-personal`, subscription), copying the oauthAccount email and org uuid so the drift guard passes, and no `ANTHROPIC_*`, `CLAUDE_CODE_*` or `CC_*` variable of the caller's shell reaches it. The real `claude` also leaves traces in the config dir beyond `projects/` (`history.jsonl`, `session-env`, the `.claude.json` project entry), and a turn there runs that account's global hooks and rules, which can write outside it. One main chat gets ONE prompt that makes it call `run_plan` with 3 chains of 2 read-only subs (each runs one `sleep`, so the run outlasts the compaction) and a main end step; the rig then calls `compact_now` on the main chat while the run is open and sends nothing else. Pass = the run file reaches `done` with every step done and the `end` alert heard, and the compaction started while a step was not done. About 3 minutes, 1 main chat, 6 subs, one save turn and one `/compact`; each run is billed, so run it once per release-gate question, not per change. Teardown kills only its daemon PID and deletes the scratch folder and the transcript folders it left under the config dir's `projects/` (`--keep` leaves both; a `--keep` run's `C:\tmp\run-plan-live-<id>` and `<config dir>\projects\C--tmp-run-plan-live-<id>-...` are yours to delete). The report with the timeline is `C:\tmp\run-plan-live-<id>.report.json`. A seeded target needs `cargo clean -p tauri -p claude-conductor` first (the build script bakes the donor's path).

- `CC_WHEN_DONE_DRY_RUN` (any non-empty value): the when-done Firing phase runs the full state machine but skips the real sleep/shutdown, logging `when_done: dry-run, would <action>` instead - set it before a live "does when-done actually fire" check so it doesn't sleep/power off the machine.

- View harness port: `playwright.config.ts` serves on 4420 by default; set `VIEW_HARNESS_PORT=<free port>` (e.g. `VIEW_HARNESS_PORT=4431 pnpm exec playwright test <spec>`) so a second concurrent run (parallel builders, two chats) gets its own vite instead of hitting "Port 4420 is already in use".

- One-off component screenshot via `pnpm run test:view`'s browser harness, no throwaway spec: `scripts/harness-shot.ps1 -Driver <ts-file> -Out <png-path>`.

- Show Joe an existing PNG in the in-app preview panel: `scripts/show-shot.ps1 -Path <png-path> [-Title <text>] [-Slug <name>]`.

- Full wdio release-gate sweep in one call (9 free specs with daemon-lifecycle last, then chat-flow/reload-dup on a fake claude, full logs kept on disk, one-line verdict per spec): `scripts/wdio-sweep.ps1` (`-Billed` adds `question-card-live`, and `-Spec question-card-live` is refused without it; `-RealClaude` bills chat-flow/reload-dup too; `-WhatIf` prints the plan without running anything). It re-launches itself under server_supervisor with its whole process tree headless, so the app windows every spec opens stay off Joe's screen, and refuses to run if the supervisor is down; `-Visible` runs it on the desktop. Supervisors older than the `/run` `dock_headless` release can let a window through for a few seconds per spec. The fake claude is `e2e/fixtures/fake-claude/claude.exe`, compiled from `claude-shim.cs` by `scripts/build-fake-claude.ps1` (csc.exe ships with Windows; `scripts/build-fake-claude.test.ps1` pins it): the committed `claude.cmd` fallback runs through cmd.exe, which refuses the 8191+ character system prompt of a chat with Use subchats on, so only the exe can start one. `chat-dashboard` keeps Use subchats on (wdio passes). `chat-flow` and `reload-dup` still call `turnSubchatsOff()` on purpose: they count `.msg.assistant` rows for a plain text reply, which a quiet-mode chat does not draw (see the comment on the helper in `e2e/helpers/new-chat.js`). `question-card-reload` also still calls it; whether its card flow passes with it dropped is untried, since that needs a sweep run with the exe.
