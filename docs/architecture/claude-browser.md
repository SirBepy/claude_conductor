# Claude's own browser

Read before editing `src-tauri/src/daemon/browser/`, `browser-extension/`, `mcp_config.rs`'s browser stamps, `runtime/` or the browser settings.

- **Claude's own browser (`src-tauri/src/daemon/browser/`).** A daemon-owned Chrome profile under `<data_dir>/claude-browser/profile`, launched as an ordinary visible window that Joe can minimize (headless trips Google's sign-in checks), driven by one `@playwright/mcp` stdio child per chat, each on its own tab. The `browser_*` tools are Playwright's own schemas from `runtime/tools.json`, listed only when `CC_BROWSER` is set (Settings `claudeBrowserEnabled`, stamped in `mcp_config.rs`), and relayed through `/browser/call`; **each chat drives either this profile or one of Joe's own browsers ("My browser", `browser/target.rs`): the `browser_target` tool (ours, listed beside Playwright's) sets it for one chat from a request like "use my Brave", kept in `ClaudeBrowser.targets` (apart from `sessions`, whose idle sweep would otherwise reset it), and Settings' `claudeBrowserMode`/`claudeBrowserMineApp`/`claudeBrowserMineProfile` only give the starting choice and what "mine" falls back to.** **"Mine" mode goes through our own bridge (`browser/bridge/`, extension source in `browser-extension/` at the repo root, replaced the Playwright MCP Bridge extension and its one-chat-per-profile lock on 2026-10-26).** The extension is a thin `chrome.*` proxy with a pinned manifest `key` (id `bridge::EXTENSION_ID`, pinned by a test); the daemon serves a loopback WS (`/extension`, plus `/cdp/<key>` per Playwright child, both token-gated) and fakes a browser-level CDP session per chat (`bridge/model.rs` holds every routing rule), so stock `@playwright/mcp --cdp-endpoint` drives it. Each chat gets one minimized window, sees only its own tabs, and `Emulation.setFocusEmulationEnabled` is forced on per tab because a minimized (hidden) page skips animation frames and Playwright's click/screenshot then time out (spike 2026-10-26, Chromium 155: every click timed out without it; with it the first of 9 two-chat runs still timed out one screenshot and the next 8 passed). `Page.bringToFront` is mapped to `tabs.update active` and `Browser.close` to closing the chat's window, so nothing raises or closes Joe's browser. Pairing is a native messaging host = this same exe (`main.rs` detects the `chrome-extension://` argv), registered under HKCU for Chrome/Edge/Brave/Chromium by the default instance only (`boot.rs`); it reads `browser-bridge[suffix].json`, so a test browser launched with `CC_DAEMON_INSTANCE` pairs with a test daemon. Chrome rejects `windows.create` bounds less than 50% on-screen, which is why windows are minimized rather than parked off-screen. The entry-point tool note covers both browsers because a chat can switch after the tool list is fixed. Google refuses sign-in in the CDP-launched profile (`chrome.rs` already drops `--enable-automation` and `--headless`, and it still refuses), which is why this mode exists. `browser_run_code_unsafe` is listed only with Settings' `claudeBrowserScriptTool` (stamped as `CC_BROWSER_SCRIPT` in `mcp_config.rs`) and refused by `ClaudeBrowser::call` while it is off. **Bumping `runtime::PINNED_VERSION` means regenerating all three files in `runtime/` together** (`package.json`, `npm-lockfile.json` = the `package-lock.json` from a scratch `npm install --save-exact --ignore-scripts`, renamed because `.gitignore` drops npm lockfiles, and `tools.json` from that version's `tools/list`), after the package safety check. Live check: `cargo test --lib -- --ignored live_browser_end_to_end` (real Chrome, flashes a window on screen for about a second).

- **Extension keepalive and drop telemetry** (`browser-extension/background.js`, `bridge/native_host.rs`, `bridge/telemetry.rs`; extension 1.1.0). Brave dropped the extension socket about every 5 minutes (76 drops on 2026-11-21) and the 20 s pings and 30 s alarm did not hold it. The worker now holds a `chrome.runtime.connectNative` port to the native host, which stays up (it loops on stdin until EOF, answering `{"type":"pair"}` with the pairing and `{"type":"keepalive"}` with `pong`) because Chrome keeps an MV3 worker alive while a native port is open (UNVERIFIED in Brave: the 30-minute idle check in the plan, P2 worker kill, settles it). Pairing itself still uses a one-shot `sendNativeMessage`. The `hello` carries `workerStartedAt`, `lastClose` (code, reason, wasClean, livedMs, kept in `chrome.storage.local` so it survives a worker restart), `nativePort`, `nativeDisconnect` and the extension `version`; the daemon logs them on connect and says whether it is the same worker as the install's previous hello ("only the socket dropped") or a new one ("the browser stopped the old one"), and logs how each extension socket ended (close frame code and reason, stream end, or read error) with its lifetime. An extension older than 1.1.0 sends none of this and parses fine. **Joe must reload the unpacked extension in Brave (`brave://extensions`, reload) once after the release that carries it**, or the old worker keeps running.

- **A live tab the browser detaches is attached again under the same session** (`bridge/reattach.rs`, `replay.rs`). Brave detaches the debugger of a tab that is still open (`target_closed`, 191 times in the logs; Bitwarden's autofill menu frame is the suspected trigger, UNVERIFIED until live check P2), and the old bridge told Playwright the page closed, which a chat reports as "I got kicked out, the tab closed". Now `debugger.onDetach` with `target_closed` on an owned tab (and re-attach budget left, 3 a minute) keeps the tab in `chat.tabs` under its session id with `TabState::Reattaching`, announces the iframe child sessions gone, then asks `tabs.get`, attaches, refreshes the url and title, turns focus emulation on, sends `Runtime.executionContextsCleared`, and replays the chat's recorded setup. The setup is whatever the chat sent for that tab session that a fresh debugger lacks (`*.enable`, `Page.setLifecycleEventsEnabled`, `Page.setInterceptFileChooserDialog`, `Page.addScriptToEvaluateOnNewDocument`, `Runtime.addBinding`, `Emulation.*` except focus emulation, `Target.setAutoAttach`), recorded in `route` by `replay::record` (a switch keeps its first position and last value, a `*.disable` or `Emulation.clear*` removes it, capped at 64). Commands for the tab that arrive meanwhile are held in `Model.held` (`Route::Hold`) and sent in order under the lock that flips the tab back to `Live`. Only a tab `tabs.get` says is gone, a failed attach, or a failed replay command sends `Target.detachedFromTarget` (and fails the held commands); `tabs.onRemoved` still drops at once, and a detach with another reason (`canceled_by_user`) is never undone. When Chrome refuses the attach with "Cannot access a chrome-extension:// URL of different extension" the tab is **parked** (`TabState::Parked`): the bridge retries every 2 s for 2 minutes, and meanwhile every command for the tab fails with `replay::PARKED_MESSAGE` ("BLOCKED ON JOE: a password manager ... do not open a new one"), never a close. A detach that arrives while a tab is Reattaching or Parked is noted, and a mark seen after the attach makes `quiet_reattach` go round again (3 rounds, then the tab is given up); a setup command held while waiting is recorded only when it is flushed, so it is never run twice; `Page.removeScriptToEvaluateOnNewDocument` is not tracked (a removed script is replayed). The model has no replay of child (iframe) sessions: their commands fail "does not belong" until the replayed auto-attach announces them again. Not yet done (later subs): parking tabs past the Playwright child, adopting Joe's tabs.

- **A chat's tabs wait out an extension reconnect** (`bridge/model/reconnect.rs`, `bridge/reconnect.rs`; no extension change). `Model::close_ext` replaces the old "drop every tab of the connection": a chat with a window or tabs on a connection whose `hello` carried an `installId` gets `Chat.reconnect` (install id, since) and **keeps its tabs, window id, session ids and setup record**. Its `ext` still names the dead connection, every tab is `TabState::Reattaching` (child sessions announced gone), so its tab commands land in `Model.held` as for a detach, and a call that needs the browser itself (`createTarget`, `closeTarget`, `bringToFront`, `Browser.close`) returns `Route::Wait` and is kept as raw text in `Model.deferred`. When a `hello` with the same `installId` arrives (`Model::rebind`, from the hello handler, or at once from `close_ext` when the new connection was up before the old one's end was noticed), the tab ids in `owners`, `held` and `reattached` are re-keyed to the new connection and the bridge runs `windows.get` on the chat's window (a missing window clears `window_id`, so the next tab opens a new one), then `quiet_reattach` for every tab (the same attach and replay as a detach), then, after those finish (10 s cap, so a parked tab cannot hold them), runs the deferred messages again. A different `installId` takes nothing. A connection that does not return within `GRACE` (90 s, 400 ms in tests) is given up on by a timer (`Model::expire`, which only touches chats whose own wait is over): the tabs close for the chat the old way. A chat whose socket ends during the wait has its window recorded in `Model.closed_windows` and closed when that install reconnects (`Model::remove_chat`). `quiet_reattach` and `reattach_once` bail without dropping the tab when their call failed because the connection itself went away (`Bridge::ext_gone`), because the re-bind starts the attach over. **When the attach answers "already attached"** (the browser kept the debugger across the worker's restart: UNVERIFIED, live check P2 worker kill settles it) `replay_session` skips `Runtime.executionContextsCleared` (a second `Runtime.enable` announces nothing, so clearing would strand Playwright) and the accumulating setup (`replay::accumulates`: scripts and bindings would be added twice). `replay_session` refuses a tab whose `Target.getTargetInfo` id differs from the recorded one (`refresh_target_info` returns false, the tab is detached and given up), because a browser that restarted inside the grace period numbers its tabs again and a re-bound id could be one of Joe's own tabs. Known limit: a chat's new call that arrives after the re-bind but before the tab attaches finish runs before the older deferred messages. Events the browser sent during the gap are lost, so a page that navigated meanwhile can leave Playwright's frame state stale until its next navigation.




- **"Blocked on Joe" detector** (`browser/blockers.rs`, run by `ClaudeBrowser::call` on every result, both browsers). `detect` reads Playwright's result text (the `- Page URL:` line, the open-tabs list, the snapshot YAML) and returns `Clear`, `Note` or `Block`. **Only strong signals block**: a sign-in or second-step URL (Google `/signin`, `/o/oauth2`, `/challenge`; PayPal `/signin`, `/checkoutnow`, `/webapps/hermes`; `login.microsoftonline.com`; `appleid.apple.com`; Roblox `/login` and its two-step page), checked on the current page and on every other open tab (a popup the chat was never told about); a live CAPTCHA (an Arkose frame, or a reCAPTCHA, hCaptcha or Cloudflare frame beside a visible "I'm not a robot"-style checkbox or button, because the invisible badges sit on ordinary pages); a code box beside two-step wording (an unnamed box counts only beside the narrow wording, and card-security-code, promo and coupon boxes never count); and a tab the password manager's frame holds (`Cannot access a chrome-extension:// URL of different extension`, which arrives as an error and is turned into the blocker result). A word alone (`captcha`, `please sign in`, ...) and a generic sign-in form (a login password box beside sign-in wording) are appended as a `Note:` and never gate, because a chat that holds the credentials signs in on such a form itself; the look-alike table in `blockers/tests.rs` (2FA settings page, blog about passwords, Google results, change-password form, card form, coupon box, invisible reCAPTCHA badge) must stay clear. A block puts `BLOCKED ON JOE: ...` as the first text part of the result (host and path only, never the query string). **The gate** (`Gate`, per chat, kept in `ClaudeBrowser.gate` and not in `sessions`, so the idle sweep cannot lift it): 2 `browser_snapshot` calls (the look that can see Joe finished) run after a block, and every call that acts is refused before anything starts (`isError` result carrying the same message). `browser_close`, `browser_tabs` (so a stale sign-in tab can be closed), screenshots, console and network reads, and `browser_evaluate` are never refused or counted; `browser_evaluate` is also never rewritten, because `capture_secret_from_page` parses its result. It opens when a result that names a page (a `Page URL` or tab list) no longer matches, or when the chat's question card is settled after the block (`DaemonState::remove_prompt` calls `blockers::note_card_answered` for a chat's own durable question card; a daemon-raised card does not count), which also marks (chat, host, kind) handled for 30 minutes so the same wall on that site does not gate again in that chat (a result with no `Page URL` has no host and is never marked). A block nobody lifts goes stale after 10 minutes. `prune_targets` forgets gone chats. A tab list alone lifts only a block that came from a tab's URL, never one from page content; the password-manager sentence counts only in an error or a short message (the same sentence sits in console output and issue threads); a skipped or dropped card settles like an answered one. UNVERIFIED: the exact result layout of the pinned Playwright MCP (`runtime::PINNED_VERSION`) was taken from its documented shape, not read from its source (node_modules reads are deny-ruled), and so was the iframe shape (`frame_names` reads an `- iframe` line and the lines nested under it, which assumes the snapshot prints a frame's `/url:` or title); re-check the regexes in `Page::parse` and `fields` and `frame_names` after a bump, and live check P3 of the plan settles it.

- **`capture_secret_from_page`** (`daemon/hooks_server/secret_capture.rs`) copies a credential shown on a page into a gitignored file without the value reaching the model. Rules: the text is not returned to the daemon until Joe allows an approval card (label, file, key, element, the page's origin and path with long opaque segments elided, the element's tag, id, name, type and text length, never a value; the card draws these open through `permission-modal/capture-facts.ts` and offers no "Always Allow"; those facts come from a metadata-only `browser_evaluate` made before the card, in which the page's own script counts and hashes the text and returns neither, and which also refuses an empty or page-sized element without raising a card; the read after the click must return the same description, text hash included, or nothing is saved, because a snapshot ref resolves only when read (so a value that changes while the card is open, such as a TOTP display, is refused and has to be saved again); the match catches drift, not a hostile page, since the description is made by script in the page's own world and a page that patches `JSON.stringify` can forge it, which is acceptable only because the text can reach nothing but the approved gitignored file; the raw fields are compared and only the card's display form is cleaned of control and bidi characters, quotes and long opaque path segments; `needsHumanApproval` in `permission-modal/gating.ts` is always true for it, so no auto-accept answers it); the write goes through `methods::secret::write_secret`, the same path as the masked `request_secret` card (inside the chat's folder, gitignored, temporary-key rules); the element is read in the daemon through the chat's own Playwright session (`browser_evaluate` with a `target`), kept as a local, and only its length is answered; an element over 4096 characters is refused so a whole-page selector cannot grab a page. The parser of `browser_evaluate`'s answer (`result_string`) is the pinned Playwright MCP's documented shape and refuses anything else generically; when `runtime::PINNED_VERSION` is bumped, re-run the ignored `live_capture_reads_a_real_page_element` (`cargo test --lib -- --ignored live_capture_reads_a_real_page_element`, real Chrome on a page printing a dummy secret).
