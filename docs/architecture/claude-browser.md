# Claude's own browser

Read before editing `src-tauri/src/daemon/browser/`, `browser-extension/`, `mcp_config.rs`'s browser stamps, `runtime/` or the browser settings.

- **Claude's own browser (`src-tauri/src/daemon/browser/`).** A daemon-owned Chrome profile under `<data_dir>/claude-browser/profile`, launched as an ordinary visible window that Joe can minimize (headless trips Google's sign-in checks), driven by one `@playwright/mcp` stdio child per chat, each on its own tab. The `browser_*` tools are Playwright's own schemas from `runtime/tools.json`, listed only when `CC_BROWSER` is set (Settings `claudeBrowserEnabled`, stamped in `mcp_config.rs`), and relayed through `/browser/call`; **each chat drives either this profile or one of Joe's own browsers ("My browser", `browser/target.rs`): the `browser_target` tool (ours, listed beside Playwright's) sets it for one chat from a request like "use my Brave", kept in `ClaudeBrowser.targets` (apart from `sessions`, whose idle sweep would otherwise reset it), and Settings' `claudeBrowserMode`/`claudeBrowserMineApp`/`claudeBrowserMineProfile` only give the starting choice and what "mine" falls back to.** **"Mine" mode goes through our own bridge (`browser/bridge/`, extension source in `browser-extension/` at the repo root, replaced the Playwright MCP Bridge extension and its one-chat-per-profile lock on 2026-10-26).** The extension is a thin `chrome.*` proxy with a pinned manifest `key` (id `bridge::EXTENSION_ID`, pinned by a test); the daemon serves a loopback WS (`/extension`, plus `/cdp/<key>` per Playwright child, both token-gated) and fakes a browser-level CDP session per chat (`bridge/model.rs` holds every routing rule), so stock `@playwright/mcp --cdp-endpoint` drives it. Each chat gets one minimized window, sees only its own tabs, and `Emulation.setFocusEmulationEnabled` is forced on per tab because a minimized (hidden) page skips animation frames and Playwright's click/screenshot then time out (spike 2026-10-26, Chromium 155: every click timed out without it; with it the first of 9 two-chat runs still timed out one screenshot and the next 8 passed). `Page.bringToFront` is mapped to `tabs.update active` and `Browser.close` to closing the chat's window, so nothing raises or closes Joe's browser. Pairing is a native messaging host = this same exe (`main.rs` detects the `chrome-extension://` argv), registered under HKCU for Chrome/Edge/Brave/Chromium by the default instance only (`boot.rs`); it reads `browser-bridge[suffix].json`, so a test browser launched with `CC_DAEMON_INSTANCE` pairs with a test daemon. Chrome rejects `windows.create` bounds less than 50% on-screen, which is why windows are minimized rather than parked off-screen. The entry-point tool note covers both browsers because a chat can switch after the tool list is fixed. Google refuses sign-in in the CDP-launched profile (`chrome.rs` already drops `--enable-automation` and `--headless`, and it still refuses), which is why this mode exists. `browser_run_code_unsafe` is listed only with Settings' `claudeBrowserScriptTool` (stamped as `CC_BROWSER_SCRIPT` in `mcp_config.rs`) and refused by `ClaudeBrowser::call` while it is off. **Bumping `runtime::PINNED_VERSION` means regenerating all three files in `runtime/` together** (`package.json`, `npm-lockfile.json` = the `package-lock.json` from a scratch `npm install --save-exact --ignore-scripts`, renamed because `.gitignore` drops npm lockfiles, and `tools.json` from that version's `tools/list`), after the package safety check. Live check: `cargo test --lib -- --ignored live_browser_end_to_end` (real Chrome, flashes a window on screen for about a second).
