# Endpoint accounts (third-party model providers)

Read before editing `src-tauri/src/accounts/endpoint.rs`, `src-tauri/src/ipc/endpoint.rs` or the Endpoint branch of `src-tauri/src/daemon/lifecycle/spawn.rs`.

- **What it is.** `AccountKind::Endpoint` runs the `claude` CLI against a third-party Anthropic-compatible endpoint (Kimi Code, DeepSeek, OpenRouter, a custom URL) with that provider's key. The CLI stays the harness; only the model behind it changes. It has no OAuth login, no claude.ai cookie and no Console login, so everything that reads those skips it (usage poll `scheduler::account_has_cookie`, `get_auth_state_map`, the drift and credentials checks in `spawn.rs`, the model probe `ipc/models/config_dir.rs`, re-auth and cookie recapture in `ipc/accounts/identity.rs`, claude.ai connectors).
- **Config.** `Account.endpoint: Option<EndpointConfig>` (`#[serde(default)]` everywhere): `preset` (`kimi_code`, `deepseek`, `openrouter`, `custom`; a label only, spawns never read it), `base_url`, `auth_style` (`bearer` or `x_api_key`), `models` (ids for the picker, each passing `is_valid_endpoint_model`). An old `accounts.json` entry loads as a Subscription account with `endpoint: null`.
- **The key** is stored exactly like an API-credit key: a DPAPI-wrapped `apikey-<id>.txt` in the data dir through `accounts::api_credit::{save_api_key, load_api_key}`. Never in `accounts.json`, never in a log (`SpawnEnv`'s `Debug` redacts both `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN`). The key is not checked against the provider when added: each vendor's check differs, so a wrong key shows at the first turn.
- **The spawn env** (`SpawnEnv::for_endpoint_account`): everything `for_account` does (OAuth token, API key and auth token scrubbed), then `ANTHROPIC_BASE_URL`; bearer sets `ANTHROPIC_AUTH_TOKEN` and holds `ANTHROPIC_API_KEY` at the empty string, x-api-key sets `ANTHROPIC_API_KEY` and leaves the token unset; and `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU,FABLE}_MODEL` plus `CLAUDE_CODE_SUBAGENT_MODEL` all pinned to the chat's model id, so a helper the chat starts inside itself stays on the endpoint. **Never set or override a User-Agent**: the CLI sends `claude-cli/...` and Kimi Code's terms forbid changing it.
- **Guards.**
  - `chat/billing.rs` `check_metered_billing_endpoint` allows `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` for this kind only; Bedrock and Vertex still refuse.
  - Model ids: `lifecycle::is_valid_model_for` takes any id matching `^[A-Za-z0-9._:/~\[\]-]{1,128}$` for an Endpoint account (plus: no leading `-`, so an id never reads as a CLI flag). Claude accounts keep the family check.
  - Voice, Ask, publishing and the model probe refuse it (`accounts::refuse_non_subscription`, `config_dir_from_resolution`).
  - Unlike API credit, an Endpoint account may be the default, a project binding, a sub's account and (opt-in `fleet_eligible`) a fleet worker.
  - **No client-repo guard.** Decided 2026-11-23: an Endpoint account is not refused by project. `ProjectConfig.payment_group: Option<String>` (`#[serde(default)]`; `"personal"` or `"client"`, `None` reads as personal) is stored only and nothing reads it yet; pc-1833 phase 1b uses it to pick a routing profile.
- **IPC** (desktop-process Tauri commands, like `add_api_credit_account`): `add_endpoint_account`, `update_endpoint_account`, `replace_endpoint_key`; removal is the ordinary `remove_account`, which deletes the key file. None is a daemon method and none has a `TRANSPORT_TABLE` row, so the key cannot cross a remote transport; `list_accounts` (P) carries the base URL and models but never the key.
- **Verified CLI behaviour** (claude CLI 2.1.325, fake local endpoint, 2026-11-23, no real calls): `ANTHROPIC_BASE_URL` is honoured and the request goes to `POST /v1/messages?beta=true`; `--model <any id>` reaches the endpoint unchanged (an unknown id only prints `[claude-code:unrecognized_model]` to stderr); with `ANTHROPIC_AUTH_TOKEN` set and `ANTHROPIC_API_KEY=""` auth is `Authorization: Bearer` with no `x-api-key`; `ANTHROPIC_DEFAULT_<TIER>_MODEL` remaps that alias; a `[1m]` suffix is stripped from the id and adds the `context-1m` beta header.
- **UNVERIFIED until a real key is tried:** each preset's base URL, auth style and model ids (Kimi Code `https://api.kimi.ai/coding/`, DeepSeek `https://api.deepseek.com/anthropic`, OpenRouter `https://openrouter.ai/api`), that OpenRouter wants the bearer style, and how each vendor's server-side cache and usage reporting behave.
- **Not here yet:** routing by role and project (pc-1833 phase 1b), the Settings UI (phase 2), fallback at a usage limit (phase 3), and Codex (phase 4). No usage tracker exists for this kind.
