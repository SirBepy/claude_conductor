# Modes

Read before editing `src-tauri/src/daemon/modes/`, `daemon/hooks_server/mode.rs`, the `[mode]` rider arms in `hooks_server/user_todos.rs` and `nudge.rs`, or the mute check in `daemon/notify_gate.rs`.

One current mode (a name, a flag list, an optional end time) lives in `<app_data>/modes{instance_suffix}.json`. Any local program sets it with `POST /hooks/mode` (`GET` reads it). A timers app owns schedules and the OS side (closing Slack, Windows DnD); Conductor stores the mode and applies it to chats, because only the daemon reaches every chat and survives restarts. Gaming is one mode with the flag `pause_chats`. Spec and Joe's picks: todo pc-1675.

- **State.** `ModeState` in `modes/mod.rs`, every field `#[serde(default)]`. A file that exists but does not parse is moved to `.bad` (`modes/persist.rs`) and the daemon starts with no mode; it is never read as empty and overwritten. Gaming's own file (`gaming-mode.json`) stays the record of what gaming parked and stopped, and nothing else.
- **Route.** Loopback only, behind the Host + Origin guard, no token (Joe's call). The body needs a `mode` key (a name, or `null` to clear): an empty object is a 400, never "end the mode". A refusal is a 400 `{"ok":false,"error":...}`; a stored mode answers 200 with the state. Names are lowercase letters, digits, `-` and `_`, 40 characters at most. An end time that has passed, or is not RFC 3339, is refused. An unknown flag is dropped and logged, never an error, so a newer timers app does not break against an older daemon.
- **Flags** (fixed vocabulary, `KNOWN_FLAGS`): `pause_chats` (gaming's park and resume, `gaming_mode::turn_on` / `turn_off`), `mute_conductor`, and four rider flags (`test_without_asking`, `take_obvious_answer`, `park_blockers`, `stop_servers_when_done`). The name `gaming` always carries `pause_chats`.
- **Switching.** `apply_with` resumes the old mode's `pause_chats` first when the new mode lacks it, stores the new state, then parks if the new mode has it. Two modes that both carry `pause_chats` cause no resume-then-park churn. The effect goes through the `PauseEffects` trait so the transitions are unit-tested with a recorder.
- **End time.** `modes::spawn` (called from `boot.rs`) adopts a gaming record from before modes existed, then checks the end time every 15 seconds; the first check waits one tick so the registry and the supervisor link are up before a resume messages chats. An unparseable stored end time counts as expired.
- **Gaming.** `set_gaming_mode` (tray, Settings) calls `modes::set_gaming`: ON switches to mode `gaming`; OFF clears the current mode only when it carries `pause_chats`. `get_gaming_mode` still reads gaming's own file.
- **The `[mode]` rider** (`modes/rider.rs`). Built only from fixed text: the caller's `mode` and `set_by` strings never go into it. Delivered once per change per chat, through one memory shared by two hooks: `UserPromptSubmit` (`user_todos.rs`, an idle chat) and `PostToolBatch` (`nudge.rs`, a busy chat, on a batch that carries no held message, because `parse_mid_turn_frame` needs a payload that is exactly one frame). A chat is told again after its context was rewritten (the compaction epoch + pid key every repeating rider uses, `user_todos::session_epoch`), and gets one end line when a note it was told goes away. A subagent's batch never reads or consumes it. A mode with no rider flag (gaming alone, mute alone) sends nothing. In tests the hooks read only `rider::set_mode_for_test`, never the machine's real file, so a `cargo test` on a machine in sleep mode stays green.
- **Mute.** `notify_gate::fire` asks `modes::mute::is_muted` and returns `true` (handled) without publishing `turn_sound` or pushing, so the gate's state advances and nothing replays when the mode ends. Question cards still appear, silently. The one sound the webview makes itself, the OS notification for a missed scheduled item, is muted by `src/shared/mode-mute.ts`: a cached flag seeded from the desktop-pipe-only `get_mode` RPC (absent from `TRANSPORT_TABLE`, like the gaming RPCs) and kept current by `mode_changed`, which `daemon_link/mod.rs` re-emits as `mode-changed`.
