# Shared mockup and preview state

Read before editing `src-tauri/src/daemon/preview/`, the `shared_mockup` MCP tool, `methods/preview.rs` or `shared-mockup-*.ts`.

- **Shared mockup (pc-1620).** One preview entry per main chat (`PreviewSnapshot.shared`, `#[serde(default)]`) whose page is a shell with empty `data-part="<id>"` regions, each filled by one sub's part (html, css, controls). `daemon/preview/shared.rs` owns the types, `compose` (defaults as `data-<control id>` on the region, css wrapped in `@scope`, a message listener) and the role checks (only a main chat creates; a part is written by the owner or one of its subs, one writer per region); the `shared_mockup` MCP tool (schema in `mcp/tool_schemas_subchat.rs`, listed for every chat) relays to `/hooks/shared-mockup`. `list_previews`/`get_preview` scope by family (`methods/preview.rs::in_family`: the chat or one of its subs). Frontend: `shared-mockup-scope.ts` (family and owner tag), `shared-mockup-model.ts` (pure rules), `shared-mockup-bar.ts` (the row of subs, the draggable popover that clamps to the panel, control changes posted into the staged frame so it never re-stages). Control values and any preview's page state are saved daemon-side in `PreviewSnapshot.view_state` (keys `ctl|<part>|<control>` and `page`), written by the `set_preview_state` RPC and broadcast as the `preview_state` notifier event (`preview-state` in the webview; withheld from paired peers) so the docked panel, the pop-out window and the phone follow each other; `prune_control_state` (in `save`) drops a control value whose control no longer exists, `page` is kept across a re-push. A page reaches `page` through `ccPreview.state.save(v)` / `onRestore(fn)` (`preview-page-state.ts`, injected into panel documents only). A choice is a `<select>`, a yes/no a switch, never chips. Part css rules that depend on a control are written `:scope[data-<id>="v"] x`. `@scope` was checked against WebView2 156 (2026-11-05). **Layout sub, shell controls, element messages (pc-1668).** The main chat names one of its own subs the layout sub (`shared_mockup` action `layout`, `SharedMockup.layout_session_id`); that sub or the owner may re-create the shell, any other sub is refused naming it. `create` also takes `controls` for the page itself (`SharedMockup.controls`, defaults as `data-<id>` on the page root, which also carries `data-cc-root`; saved values use `ctl|shell|<id>`, and `shell` is not a legal region id). The `message_shared_element` RPC (desktop pipe and phone, never a paired peer; `daemon/preview/shared_message.rs`) takes `{id, element, text}`, delivers the text as a user message to the region's writer or, for `shell`, the layout sub (else the main chat), and queues one `back.rs` element line (`ElementNote`: element and target name only, never Joe's text) for the main chat unless it was the target.
