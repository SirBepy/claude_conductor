# Phone link (Android tunnel, stream heartbeats, journals)

Read before editing `android/src-tauri/src/iroh_tunnel.rs`, `journal.rs`, `android/src/app.js`, `daemon/remote_ws_pump.rs`, `remote_send_dedupe.rs`, `methods/link_journal.rs`, `global-stream.ts`, `http-transport.ts`, `connection-state.ts` or `link-journal.ts`.

- **Phone link module map (2026-11-12).** How the Android app stays connected, and where to read what happened. **Tunnel** (`android/src-tauri/src/iroh_tunnel.rs`): one shared QUIC connection per PC, dialed under the `Slot` lock. A failed dial is shared with every caller that queued behind it; a lost connection (wake-up, close, invalidation, failed call) sets `needs_fresh_endpoint`, so the next dial binds a fresh endpoint FIRST and falls back to the old one only if the bind fails; at most one rebind per call, the second attempt stays on that endpoint with `RETRY_ATTEMPT_TIMEOUT`; `watch_for_stop` abandons a dial the process slept through (wall clock, `STOP_GAP`); `last_alive` is stamped on every exit of `connection()`. The watchdog (2s) also counts ticks with no received datagram while a stream is open (`quiet_step`): `network_change()` at `QUIET_NUDGE` (8s), drop at `QUIET_DEAD` (12s). The QUIC idle timeout stays 30s on purpose (iroh rides out relay reconnects; a shorter one was reviewed and rejected). The journal (`journal.rs`) is served on its own loopback port, the tunnel port + 1, with CORS for the tunnel's origin only, and never dials; the page must not read it from its own origin, because the WebView reuses kept-alive connections that are already spliced to the PC (`forward()` still answers `GET /__tunnel/journal` on a fresh connection). It holds 200 events ( `bind`/`rebind` with the first 8 hex of the phone's endpoint id, `dial_ok ms=`, `dial_fail`, `resume`, `slept`, `tick_late`, `quiet`, `dead`, `drop`). `probe_iroh_tunnel` dials before `android/src/app.js` leaves the shell. **Daemon**: a session stream opened with `?hb=1` gets the heartbeat frame every `GLOBAL_HEARTBEAT_INTERVAL` from all three pumps and during `wait_for_respawn`, never without it (a paired machine's relay passes every frame on as a chat event); the global stream answers `{"method":"ping"}` with a heartbeat and resends the instances snapshot on `Lagged` (`remote_ws_pump.rs`). `POST /api/sessions/:id/send` runs detached from the request (`run_detached`: a dropped request used to leave `busy` latched until the 20-minute sweep) and dedupes on `client_msg_id` (`remote_send_dedupe.rs`, memory only, success only, 30 min). `IrohTunnel::close()` runs on the daemon's normal exit so clients get a close frame. `report_link_journal` (`methods/link_journal.rs`, mask `P`) writes `[phone-link] dev=<device> <line>` into `daemon.log`; stream opens and closes log `[remote-ws] dev=<device> kind=<phone|peer> ...`. **Page** (phone transport only): `global-stream.ts` pings a stale-looking open socket on resume instead of dropping it; the per-chat branch of `HttpTransport.listen` has its own watchdog (`CHAT_STREAM_STALE_MS`, acts only once a heartbeat was seen) and sends a synthetic `events_lagged` on every reopen; `wireChatRecoveryHeartbeat` keeps the 15s revive for the desktop only (phone: 60s visible-only re-read, one pass on resume); `BACKGROUND_READS` in `connection-state.ts` lists the polls that must never raise the "Waiting for your PC" strip (add a new poller's method there); `isAndroidShell()` (`window.ConductorPush`) gates the hidden slowdown (prompt poll 5s, inside the daemon's 8s render-confirm window); `link-journal.ts` records page events and uploads them with the tunnel's. A stable tunnel id in `iroh tunnel: connection from <id>` lines is the paired Mac's dialer (one ephemeral key per process), a changing one is the phone (random key per bind). Scratch analysis scripts for that log: `.for_bepy/phone-disconnect/`.
