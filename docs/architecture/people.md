# People system

Read before editing `src-tauri/src/people/`, `daemon/methods/people.rs`, `daemon/hooks_server/people.rs` or `daemon/methods/drafts_store/people_resolve.rs` (`write_draft`'s person gate).

- **Voice-note triage reads the same client notes** (`daemon/voice_triage/projects.rs`, docs/architecture/voice-notes.md "What R7 built"): it joins a Conductor project to the client whose `repos:` lists the project's name or folder name (`people::client_for`), and hands the model the client name with every repo that client lists, so a note that names only a client can reach the right repo. It is read-only here: it never writes `People/` or a client note.
- **People system: the Obsidian vault is the only store.** `src-tauri/src/people.rs` reads `People/*.md` plus client notes (any vault-root note whose frontmatter lists `repos:`; slug = lowercased note name). `daemon/methods/people.rs` serves the one `person` MCP tool (`find`/`remember`, routes `/people/find` and `/people/remember`) and the per-turn "People on <client>" rider; the caller's client comes from its own Conductor project's name/folder matched against `repos:`, never from an argument. `write_draft`'s person gate resolves client-only nicknames through the same lookup. The questionnaire wording lives in the global `/people` skill.
