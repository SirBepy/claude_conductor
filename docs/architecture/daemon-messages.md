# send_message kinds and rejected sends

Read before editing `daemon/hooks_server/messages/`, `rejected_sends.rs`, `mcp/tool_schemas_coordination.rs` or `scripts/release-report.ps1`.

- **`send_message` requires a `kind`; the caps live in `daemon/hooks_server/messages.rs`.** The 12 kinds, per-kind `text` caps, which kinds take or refuse a `verdict`, and the report-only/correction-only/do_this-only fields are all enforced there (`validate_send`), mirrored in `mcp/tool_schemas_coordination.rs`. A kindless or over-cap call is `ok:false` naming the fix, never a decode error, because a chat spawned before the field existed learns it from that error. The daemon stores nothing about kinds: the chat reads them from the `tool_use` input in the transcript, and derives old-turn shrinking (only the newest turn is full size) from that same transcript, so nothing about it is persisted.

- **A `send_message`/`update_message` the daemon rejects (over its cap, a malformed field) or any `ValidatedJson` request that fails to decode, or an `ok:false` from a handler error on any other relay route (turn status, plan, schedule, drafts, people, jarvis, channel, todos, dashboard card, subchat tool, shared mockup; through `rejected_sends::reply`) draws nothing in the chat.** `daemon/hooks_server/rejected_sends.rs` appends it to `<data_dir>/rejected-sends.jsonl` (rotates to `.old` past 512KB) and `scripts/release-report.ps1` (run by `/release` step 1d through `.claude/release-reports.txt`) groups those shapes since the last `VERSION:` commit, next to the app log's ERROR and WARN lines. The old red "Failed to send" pill per rejection is gone (a model resending until one passes stacked six); a failed row is a hidden `failed-marker` element. Read the report for an ERROR, or a shape with a high count.
