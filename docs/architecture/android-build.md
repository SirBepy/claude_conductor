# Android build, toolchain and test notes

Read before building, testing or changing the build setup of `android/`, or `scripts/bootstrap-worktree.ps1`'s Android part.

- Android: `cargo tauri android build --target aarch64 --apk` from `android/`, with `ANDROID_HOME`, `NDK_HOME` and `JAVA_HOME` set. **Never invoke `gradlew` directly on a fresh checkout.** Two required build inputs are gitignored and machine-specific, so git alone cannot produce a buildable tree: `gen/android/.../generated/TauriActivity.kt` (codegen output - `MainActivity.kt` extends `TauriActivity` with NO import because it is emitted into the app's own package, so a raw gradle build fails with "Unresolved reference: TauriActivity" and the fix is to run the codegen, NOT to add an import), and `gen/android/tauri.settings.gradle` (hardcodes an absolute path into this machine's cargo registry, pinned to the current tauri version). `scripts/bootstrap-worktree.ps1` runs `cargo tauri android init` (which writes neither: they come from a full android build sync) and then copies both, plus `keystore.properties`, `app/google-services.json`, `app/tauri.build.gradle.kts` and `app/tauri.properties`, from the main checkout when missing, so `gradlew :app:testArm64DebugUnitTest` runs in a fresh worktree after only the script (verified 2026-11-12); the main checkout must have built Android once (auto-detects `ANDROID_HOME`/`NDK_HOME`/`JAVA_HOME` from their standard install locations, since none of the three are set as persistent env vars on this machine); after a tauri version bump, rebuild in the main checkout first, since the copies carry its tauri version. A release build now fails loud (`gen/android/app/build.gradle.kts`) instead of silently signing with a different identity if `gen/android/keystore.properties` is missing - see `C:\Users\tecno\.android-keystores\README.txt` for the shared key. A third gitignored input, `gen/android/app/google-services.json` (Firebase project `claude-conductor-62582`), is needed by EVERY Android build because the Google Services gradle plugin is applied; CI writes it from the `ANDROID_GOOGLE_SERVICES_JSON_BASE64` secret, and a fresh local checkout gets it by `base64 -d` of that secret's source or a re-download from the Firebase console (Project settings > Your apps).

- **`android/`'s tests run on the HOST target, no NDK needed:** `cargo test --manifest-path android/src-tauri/Cargo.toml` (verified 2026-08-12, todo #620: 8 tests pass, ~2m45s cold / 0.34s warm). It is a separate workspace but shares the global `D:/cargo-target` target-dir with the main crate, so it is release-gated / on-demand, NOT part of the routine per-edit floor - run it manually before an android-touching release, and never concurrently with another cargo command in this repo (shared target-dir lock).

- **Cross-compiling Rust to `aarch64-linux-android` needs four more env vars.** Without them `ring`'s build script cannot find the NDK's clang and the build dies in a C compile, which reads like a broken dependency rather than missing toolchain config: `CC_aarch64_linux_android` and `CXX_aarch64_linux_android` -> `<NDK>/toolchains/llvm/prebuilt/windows-x86_64/bin/aarch64-linux-android28-clang.cmd`, `AR_aarch64_linux_android` -> `llvm-ar.exe` beside it, `CARGO_TARGET_AARCH64_LINUX_ANDROID_LINKER` -> that same clang. The `28` matches `minSdkVersion 28` (read from `android/src-tauri/tauri.conf.json`, not hardcoded). `scripts/bootstrap-worktree.ps1` now writes these into a gitignored `android/.cargo/config.toml` `[env]` block (same pattern as `src-tauri/.cargo/config.toml`'s `RUST_TEST_THREADS`), so a plain `cargo build`/`cargo tauri android build` from `android/` picks them up automatically - re-run the script if the NDK path changes. Verified 2026-08-08 building `android/` with iroh; iroh's defaults select `tls-ring`, not `aws-lc-rs`, so no extra feature juggling is needed.

- **Iteration scripts:** `scripts/build-install-android.ps1 [-Fresh]` wraps the build+`adb install` loop (auto-detects the one connected device, streams output so a stuck Gradle daemon is visible). `scripts/regen-android-icon.ps1 -Scale <f> -MarginRatio <f> [-BackgroundColor <hex>] [-Confirm]` wraps the launcher-icon pipeline documented in `assets/icon/README.md`.
