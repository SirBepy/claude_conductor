# Claude Conductor

Cross-platform Tauri 2 app (Rust + vanilla JS webview). Usage monitoring via cookie-authenticated HTTPS polling of the claude.ai usage API (Chrome/CDP runs only during the one-time login flow to capture the sessionKey), interactive Claude chat sessions (daemon-hosted persistent `claude` per session), and hooks/MCP permission relay.

## Project

Type: other (Tauri 2 / Rust + vanilla JS webview)
Deploy: GitHub Releases; CI builds Windows (NSIS) and Apple Silicon macOS (DMG, restored 2026-08-31). Intel macOS and Linux (DMG / DEB + AppImage) stay paused mid-feature-work, to be restored per dev
- **Releases:** `src-tauri/tauri.conf.json`'s committed `version` is intentionally stale locally, CI-owned (`desktop-build.yml` rewrites it). **Windows publishes first**; until `publish-macos` lands a Mac client's update check ERRORS. If macOS fails after Windows shipped, rerun with `gh run rerun <run-id> --failed` within 30 days, never a full rerun or a same-version push (`check` skips once the tag exists, so macOS never publishes); a code fix for macOS needs a version bump. GitHub's "immutable releases" setting must stay off. Before touching `.github/workflows/` or recovering a failed release, read docs/architecture/release-shape.md.

## Structure

`src-tauri/src/` Rust backend, `src/` frontend SPA, `src-tauri/tauri.conf.json` Tauri config, `android/` a SEPARATE minimal Tauri 2 Android crate (own workspace + lockfile) whose bundled shell just stores a server URL and hands off to the daemon-served SPA

## Commands

- Dev: `cargo tauri dev` (runs from anywhere in the repo; the Tauri CLI auto-locates `src-tauri/tauri.conf.json`)
- Verify: `cargo build --manifest-path src-tauri/Cargo.toml`. **Needs a built `dist/` first on a fresh checkout, or this fails as `RustEmbed` error `../dist does not exist`** - that reads like a broken path, not a missing frontend build. `dist/` is `tauri.conf.json`'s `build.frontendDist` (`../dist`, embedded at compile time) and is gitignored, and `scripts/bootstrap-worktree.ps1` does not produce it. Run `pnpm exec vite build` once first (cheaper than `pnpm run build`, which also reruns the `export_types` cargo test via its `prebuild` script) to unblock `cargo build`/`cargo check`/`cargo test` on `src-tauri`.
- **Frontend unit tests: `pnpm vitest run --poolOptions.threads.maxThreads=5 --poolOptions.threads.minThreads=1`.** Never `--pool=forks --poolOptions.forks.singleFork=true`: cramming every file into one process leaks timers/globals and produces ~15 FALSE failures in files you never touched (`boot-render-gate`, `shortcuts`, `auq-*`, `chat-renderer-edits`), which reproduce on pristine HEAD. The flags above satisfy the concurrency cap without lying.
- Update `vendor/tauri_kit`: `git submodule update --remote vendor/tauri_kit`, then `pnpm tsc --noEmit` to catch breaking kit changes.
- `pnpm run check:css-vars` catches a `var(--name)` reference with no matching declaration anywhere - the silent-fallback bug class swept by hand in 61ba939d and 5ee6dc0c.
- `pnpm run check:view-spec-coverage [files...]` names every view/wdio spec that depends on a changed source file but was not itself changed; a spec that only drives the rendered UI needs a `// asserts: <src path>` header. Details in docs/architecture/dev-checks.md.
- Worktree bootstrap: `powershell -File scripts/bootstrap-worktree.ps1` (not `pwsh`) once right after `git worktree add`/`EnterWorktree`, before any build or verify; idempotent. Details in docs/architecture/dev-checks.md.

- Android: build with `cargo tauri android build --target aarch64 --apk` from `android/`. **Never invoke `gradlew` directly on a fresh checkout**: run `scripts/bootstrap-worktree.ps1` (or `cargo tauri android init`; re-run it after a tauri version bump or NDK path change) first, because the gitignored `TauriActivity.kt`, `tauri.settings.gradle` and `google-services.json` are required build inputs, and never fix "Unresolved reference: TauriActivity" by adding an import. `android/`'s host tests are `cargo test --manifest-path android/src-tauri/Cargo.toml`: release-gated, never concurrent with another cargo command (shared target dir). Before building or changing `android/`, read docs/architecture/android-build.md.
- Dev rigs and scripts (details in docs/architecture/dev-rigs.md, read before using one): `scripts/live-verify.ps1 up|eval|shot|down` (isolated app; `up -Visible` can take Joe's typing); `scripts/phone-verify.ps1 up|status|down` (isolated daemon for phone-path checks, build it first, it never runs cargo); `scripts/wdio-sweep.ps1` (`-Billed` and `-RealClaude` bill real claude, `-WhatIf` plans); a dev daemon beside the live app needs `CC_DAEMON_INSTANCE` set so it never fights the production daemon for 27183; set `CC_WHEN_DONE_DRY_RUN` before any live when-done check so the machine does not sleep; set `VIEW_HARNESS_PORT=<free port>` for a second concurrent view-harness run (default 4420).

## Rules

- Keep `README.md` in sync when auth flow, tray behavior, scraping approach, or project structure changes. README is user-facing; CLAUDE.md is developer rules only.
- Chat hub is subscription-only, with ONE opt-in exception. `check_metered_billing` in `chat/billing.rs` refuses to spawn if `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, Bedrock, or Vertex env vars are set. The exception is an `AccountKind::ApiCredit` account (`accounts/api_credit.rs`), which bills the Max plan's monthly API credit. Its chat spawn alone carries `ANTHROPIC_API_KEY`, checked by `check_metered_billing_api_credit`, which still refuses the auth token, Bedrock and Vertex. Every other spawn path (voice, ask, publish, model probe) refuses that account kind. It is never a default, a project binding, or fleet-eligible.
- **API-credit balance needs a Console login (`console-session-<id>.txt`), not the claude.ai one**: each cookie gets 403 on the other's org. `limit_usd` is in cents. The cap gate refuses new turns with `API_CREDIT_BLOCKED` (-32007, HTTP 402 on the REST send) on a $0 `subscription_api_credit` tranche, a reached spend limit, or purchased credit with no Max grant this cycle; unknown figures never create a block, and a non-auth fetch error only keeps a block already known. Before editing `daemon/api_credit.rs` or `accounts/api_credit.rs`, read docs/architecture/api-credit.md.
- **One ask channel: the `ask_user_question` MCP tool. The builtin `AskUserQuestion` is never used.** `--disallowedTools AskUserQuestion` is passed at spawn by `daemon/claude_config/args.rs` (chat sessions), which also get the `PreToolUse` hook safety net (`hooks_server/question.rs`) and the MCP tool itself (`--mcp-config`). The builtin's schema has no `domain`/`badges`, so its cards can never render the chips, and only the MCP path sets `supportsExtras` (the review step's free-text box). Do not re-enable it or add a second ask path.
- **`send_message` requires a `kind`; the caps live in `daemon/hooks_server/messages/`** (`validate_send`), mirrored in `mcp/tool_schemas_coordination.rs`. A kindless or over-cap call is `ok:false` naming the fix, never a decode error, and the daemon stores nothing about kinds. A rejected `send_message`/`update_message`, a `ValidatedJson` decode failure or a relay-route handler `ok:false` (a new relay route answers through `rejected_sends::reply`) draws NOTHING in the chat: `rejected_sends.rs` appends it to `<data_dir>/rejected-sends.jsonl`, and `scripts/release-report.ps1` (`/release` step 1d) groups it with the app log's ERROR and WARN lines, so read that report for an ERROR or a high-count shape. Never bring back a visible "Failed to send" pill per rejection. Before editing those files, read docs/architecture/daemon-messages.md.
- Custom IPC commands need only `generate_handler!` registration - no `capabilities/default.json` entry. Capabilities entries ARE required for plugin permissions and new window labels (window labels must match `src-tauri/capabilities/default.json`, e.g. the `session-*` pattern).
- **Any field added to a settings-reachable struct (`Settings`, `ProjectConfig`, `RetentionPolicies`, ...) needs `#[serde(default)]`.** A present-but-incomplete sub-object (the field's key exists but a newer sub-field doesn't) fails deserialization for the WHOLE `settings.json`, not just that field - confirmed data loss, todo 785, Joe lost 7 top-level settings twice on 2026-08-22.
- **Decided 2026-08-08 (todo 521): the STT sidecar is NOT bundled into the installer** (dictation works only from a source checkout; bundling a `.venv` would add 2-4GB for one user). Details in docs/architecture/stt-sidecar.md.
- **Multi-machine federation** (`src-tauri/src/daemon/machines/`, `daemon/remote_transport_table.rs`). Hard rules: route a session id to a peer only through `machines::mirrored_owner`, never `MirrorState::owner_of` directly, or a peer can claim a local chat's id; `daemon/methods/spawn_chat/forward.rs` and `machines/forward.rs` are deliberately separate forwarders, do not merge them; never trust a request payload's claimed machine identity, read `ctx.transport` (`rpc::Transport` is `Local`, `Phone` or `PeerMachine(id)`, and `ConnectionContext::remote` is true only for `Phone`); `TRANSPORT_TABLE` in `daemon/remote_transport_table.rs` gates every remote method (absent = desktop-pipe only; every row needs a rationale comment and every `machine: true` mask an allowlist test entry; a method for a mirrored session must be `PM` or `M`); `MirrorState` drops any row that already carries a `machine` tag and nothing forwards a call that arrived from a `PeerMachine`; `Instance.machine`, `is_remote` and session kind imply nothing about each other; clients send `session_id` alongside a prompt's `request_id`/`id` so answers forward, and `peer_scope.rs` enforces each peer's "Can drive chats" switch on `/api/rpc` and the REST send route. Reach `TRANSPORT_TABLE`/`TransportMask` by their own module path, not `remote_handlers` (only `allowed` is re-exported there); only the default daemon instance advertises an iroh tunnel, so pair two local instances by a direct `http://127.0.0.1:<port>` URL. Before editing machines, transports or the machine UI, read docs/architecture/multi-machine.md.
- **Subchats** (daemon-side code lives in `src-tauri/src/daemon/subchats/`; add to it, not to lifecycle or hook files). Hard rules: ask "is this a sub" only through `subchats::is_sub(&Instance)` (`subchat_of`, never `worker_of`: a sub must not wake its parent the way a Jarvis worker does); a sub's text never travels inside an `is_meta` message (only as hook context framed as data); only the daemon writes the decisions log, so no chat carries it; `subchats::on_finished` is the one hook a finish fires, `subchats::role_launch` decides sub, main chat or neither on every launch, `routing.rs` stamps `display_session_id` on question, permission and secret payloads (`session_id` stays the answer target), and `cards::raise_card` is the only way the daemon puts its own question card in a window; every field of `held.json`'s entries except the sub id has `#[serde(default)]` and an unreadable state file or entry is kept as `.bad`, never read as empty (`held[suffix].json` is per daemon instance so a test daemon never wipes the live queue; `ProjectConfig.subchat_writers` is parsed and ignored, there is no project toggle); every writing sub gets its own worktree (a writer in a folder that cannot have one takes the one-writer slot in `writers.rs`), merged back with a rebase and `merge --ff-only --no-overwrite-ignore`, removed only when merged, clean and with no unpublished submodule commit; a sub queued for the writer slot is never blocked, nudged or carded as stalled, and a main chat never schedules prompts to poll its subs. Before editing subchats code or UI, read docs/architecture/subchats.md.
- **Main-chat retros** are written by the `main_chat_retro` MCP tool (`daemon/subchats/retro.rs`) when Joe tells a subchats-mode main chat to close; the daemon stamps the frontmatter itself, never the chat, and the global `/close` skill is deliberately untouched. Before editing retros, read docs/architecture/main-chat-retros.md.
- **People system: the Obsidian vault is the only store.** The caller's client comes from its own Conductor project's name/folder matched against a note's `repos:`, never from an argument. Before editing `src-tauri/src/people/`, `daemon/methods/people.rs`, `daemon/hooks_server/people.rs` or `daemon/methods/drafts_store/people_resolve.rs`, read docs/architecture/people.md.
- **Claude's own browser** (`src-tauri/src/daemon/browser/`). Hard rules: never launch the browser headless (it trips Google's sign-in checks); each chat drives either the daemon's profile or one of Joe's own browsers ("My browser"), chosen with the `browser_target` tool and kept in `ClaudeBrowser.targets`, apart from `sessions`; "mine" mode goes only through our own bridge (`browser/bridge/`, extension in `browser-extension/`), whose manifest `key` and id `bridge::EXTENSION_ID` are pinned by a test; nothing may raise or close Joe's browser (`Page.bringToFront` maps to `tabs.update active`, `Browser.close` closes only the chat's own minimized window, never park windows off-screen); in "mine" mode `Emulation.setFocusEmulationEnabled` stays forced on per tab (a minimized page skips animation frames and Playwright clicks time out); `browser_run_code_unsafe` is listed only with Settings' `claudeBrowserScriptTool` and refused by `ClaudeBrowser::call` while off; bumping `runtime::PINNED_VERSION` means regenerating `package.json`, `npm-lockfile.json` and `tools.json` in `runtime/` together, after the package safety check. Before editing the browser, bridge, extension or `runtime/`, read docs/architecture/claude-browser.md.
- **`pnpm tsc` needs `MachineRef` in `src/types/ipc.generated.ts`.** It's declared in `src-tauri/tests/export_types.rs`; regenerate with `cargo test --manifest-path src-tauri/Cargo.toml --test export_types` after changing `Instance` or any machine-federation type.
- **Shared mockup.** One preview entry per main chat: only a main chat creates it, a part is written by the owner or one of its subs, one writer per region. A choice control is a `<select>`, a yes/no a switch, never chips, and a part css rule that depends on a control is written `:scope[data-<id>="v"] x`. `preview_state` is withheld from paired peers; only the layout sub or the owner may re-create the shell, `shell` is not a legal region id, and `message_shared_element` (never a paired peer) the element note it queues carries only the element and target name, never Joe's text. A page keeps its state through `ccPreview.state.save(v)` / `onRestore(fn)`. Before editing `daemon/preview/`, the `shared_mockup` tool or `shared-mockup-*.ts`, read docs/architecture/shared-mockup.md.
- **Chat dashboard** (`src/shared/chat/dashboard/`, `src/views/sessions/chat-dashboard/`). Hard rules: to add a card, add a derive function and one entry to `ZONES` in `dashboard-model.ts` (column, order, derive returning null when empty) and its renderer in `dashboard-zones.ts`'s `ZONE_VIEWS` (typed against `ZoneId`); never touch the transcript renderer for a card; the Answers and Subchats cards own their DOM (`.ax-host`, `.sx-host`) so a re-derive never wipes them; every model battery goes through `modelBatteryHtml(model, effort)`; a new optional card adds its id to `SECTION_DEFAULTS` and one row to `DASHBOARD_SECTIONS` in `chat-defaults.ts`; view-harness `mountView` pins `chatView: "messages"` unless a spec passes `chatView: "dashboard"`; the phone always draws Messages; "Pin to sidemenu" (`Instance.pinned_to_sidebar`) replaced Move to sidebar, so nothing in the UI calls `move_sub_to_sidebar`. Before editing the dashboard or its daemon side (`daemon/methods/answers.rs`, `quick_views.rs`, `sub_view.rs`, `ask/answer_state.rs`) or `sidebar-entries.ts`, read docs/architecture/chat-dashboard.md.
- **A markdown blockquote is a quote of a person, drawn as a reply bubble on every surface** (`.md-quote` via `renderMarkdown`, one style `blockquote.md-quote` in `chat-messages-markdown.css`). Give a new markdown surface no blockquote rule of its own, and never bring back a transcript copy card for blockquotes: paste-ready text goes in a fenced code block. Details in docs/architecture/markdown-quote.md.
- **Phone link** (Android tunnel, stream heartbeats, journals). Hard rules: a new background poller's method goes in `BACKGROUND_READS` in `connection-state.ts` so it never raises the "Waiting for your PC" strip; a session stream gets the heartbeat frame only when opened with `?hb=1` (a paired machine's relay passes every frame on as a chat event); the QUIC idle timeout stays 30s on purpose; the tunnel journal is served on its own loopback port (tunnel port + 1) and the page must not read it from its own origin; `POST /api/sessions/:id/send` runs detached (`run_detached`) and dedupes on `client_msg_id`; `isAndroidShell()` gates the hidden slowdown (prompt poll 5s, inside the daemon's 8s confirm window). Before editing the Android tunnel (`android/src-tauri/src/iroh_tunnel.rs`, `journal.rs`, `android/src/app.js`), `daemon/remote_ws_pump.rs`, `remote_send_dedupe.rs`, `methods/link_journal.rs`, or the phone page's stream and journal files (`global-stream.ts`, `http-transport.ts`, `connection-state.ts`, `link-journal.ts`), read docs/architecture/phone-link.md.
